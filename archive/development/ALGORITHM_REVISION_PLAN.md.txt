**FORCE algorithm alignment revision plan**

Revise `ccae8be07aa4eb9d044f0d01fa1d23ddb7c8007c` using the formal estimator in the published FORCE paper as the mathematical specification. Preserve the corrected batch mathematics already present. Complete the numerical and streaming implementation, and validate intermediate quantities against independent references. Published timing and RMSE values are not acceptance criteria.

The reference is [Mathematics 2026, 14, 191](https://doi.org/10.3390/math14010191), available locally as `mathematics-14-00191.pdf`. The reviewed PDF SHA-256 is `a44f2a3a7e085b40f979e1260c6a977f1c71e64e499295bd5b3c9908cc17afac`. This document records the revision specification; implementation and verification status are maintained in `VERIFICATION.md`.

The first two commits' `src/force/core.py` have the identical Git blob `5ead540b28b4fe41edb5f40a58d7c8a2c002faaa`. Their `estimators.py`, convergence script, and tests are also byte-identical. The first revision therefore did not repair the original estimator. It added exact baselines using different tails, TER, centering, and cap settings; its FORCE-versus-exact comparison could not isolate quantile approximation error.

In both early commits, with `C = Phi^-1(0.95) - Phi^-1(0.05)`, the regular arithmetic gives

```text
scale = (q75 - q25) / 1.349
TER   = (q95 - q05) / (scale * C)
width = lambda * TER * scale = lambda * (q95 - q05) / C
```

This is a different bound policy from the published equations. Both early commits also contain the incorrect `/100` exact reference and a silent FastMCD-to-Pearson fallback. The first commit's main benchmark uses 15% uniform contamination; the second changes that to 10% and adds exact trimming baselines. Those changes do not repair the estimator's functional definition.

**Mathematical decisions that govern the revision**

| Paper item | Implementation decision |
|---|---|
| Section 2.2.1 and Eq. 3 | Keep the standard five-marker P² recurrence. The printed desired-position formula is malformed; record the correction rather than reproducing it. |
| Eqs. 6–10 | Keep `mu=q50`, `sigma=(q75-q25)/1.349`, `TER=max(1, abs(q99-q50)/(abs(q50-q01)+epsilon))`, and inclusive `mu ± lambda*TER*sigma` bounds. Preserve the stated degenerate lower-tail rule. |
| Eq. 11 | Preserve a finite TER cap as an explicit option. Keep the equation-faithful default uncapped. Disabling TER is an explicitly different bound policy. |
| Eq. 13 versus Algorithm 1 | Use separate accepted counts, means, variances, and co-moments for every pair. Correct the pseudocode's missing pair indices. |
| Algorithm 1 | Preserve final bounds computed from the complete first traversal, then evaluate every observation against those fixed bounds in a second traversal. |
| Remark 9 and Eq. 14 | Add a separately named causal delayed-window variant with explicit initialization, scheduling, and output semantics. Its historical acceptance decisions differ from final-bound batch decisions. |
| Theorem 1 | Do not promise 25% end-to-end breakdown for uncapped TER or approximate P². Record the counterexamples and missing conditions. A cap alone does not prove the claim. |
| Proposition 1 and Corollary 1 | State the conditional trimmed-correlation target and its assumptions. Rejecting contamination does not generally make it equal to untrimmed clean correlation. |
| Claimed root-N rate | Quantile consistency alone does not establish that rate; a rate for the estimated-bound contribution and suitable moment conditions are also needed. Do not encode the claim as a test expectation. |
| Theorem 3 | Report quantile state O(p), dense pair state/output O(p²), chunk workspace O(Bp), and caller/source storage separately. Retained diagnostics are not peak workspace. |

Keep the public constant-feature convention (unit diagonal, undefined off-diagonal entries zero) for compatibility, but expose accepted counts and degeneracy status. A zero returned for an undefined pair must be distinguishable from an estimated zero correlation. Pairwise rejection can produce a non-positive-semidefinite matrix; a PSD projection would be a separately named postprocessing step, not part of Eq. 13.

The fixed epsilon and the one-sided TER ratio have consequences for invariance. Do not require full-estimator sign-reflection invariance, or exact scale invariance near the epsilon branch. Test arithmetic invariance using fixed bounds and unchanged accepted masks, and assess the full bound policy under its actual definition.

**Ordered implementation work**

1. **P0 — Lock the estimator specification and independent oracle.**

   Files: `src/force/core.py`, `src/force/trimmed_pearson.py`, `tests/test_core.py`, `tests/test_estimators.py`, and `VERIFICATION.md`.

   Preserve current tails, TER, inclusive acceptance, and pair centering. Write a small test-only reference that independently computes Eq. 6–13 quantities and, for every pair, selects jointly accepted rows and computes ordinary Pearson on that subset. Expected results must not call the production bounds or correlation helpers. Compare default P² output against the reference using the production quantiles as supplied inputs; separately compare exact mode using independently computed exact quantiles. This distinguishes errors in quantiles, bounds, masks, and moments.

   Extend the existing tests rather than replacing their valid coverage. The current end-to-end Eq. 13 reference test exercises exact-cutover mode; add the normal P² path, asymmetric masks, ties, repeated observations, constant features, and zero/one/two accepted rows. Retain a hand-checkable median-versus-mean regression: `[[0,0],[0,0],[0,1],[1,0],[2,2]]`, with fixed bounds accepting the first four rows, must yield off-diagonal `-1/3`, not zero.

   Acceptance: every intermediate quantity matches its independent reference within an explicitly stated floating-point tolerance; the shifted perfect-correlation example that exposed the old `/100` bug returns one. Exact and P² variants differ only in their quantile backend when their policies are otherwise equal. Historical snapshot fixtures remain isolated from the primary correctness suite.

2. **P0 — Repair numerical finalization and define failure behavior.**

   Files: `_compute_trimmed_corr_numba`, covariance normalization, bounds computation, and numerical tests.

   The current `sqrt(sum_xx * sum_yy)` can overflow or underflow while each square-sum is representable. A fixed-mask reproduction with `X=[[-2,-1],[-1,-1],[0,0],[1,2],[2,1]]` gives correlation `0.8488746876271654` at unit scale, zero at scale `1e100`, and one at scale `1e-100`. All bounds are scaled with the data, so acceptance is unchanged. This is a current implementation defect, independent of historical-table reproducibility.

   Normalize using separate norms and numerically safe operation ordering. Add scaled accumulation or explicitly detect and report unsupported arithmetic when the moments themselves cannot be represented. Review `fastmath=True` around overflow checks and clipping: clipping must not convert a nonfinite intermediate into a valid-looking correlation. Apply compatible policies to baseline covariance normalization. Check bounds for nonfinite arithmetic and report failures rather than accepting everything through accidental infinite bounds.

   Preserve genuine zero-variance and insufficient-count behavior, with diagnostics. For independent P² trackers whose quartiles cross, retain the documented warning/degenerate-scale behavior and surface a status; do not silently sort the five estimates, which would change their meaning. A stricter error mode can be offered explicitly.

   Acceptance: the rescaling reproduction returns the same correlation at all three scales, within tolerance; large offsets and unequal coordinate scales are tested; unsupported ranges fail explicitly. Use a well-scaled or higher-precision independent oracle so the reference does not repeat the production overflow. Tests distinguish arithmetic limitations from the fixed-epsilon bound policy. No fallback to Pearson, silent TER cap, or PSD repair is introduced.

3. **P1 — Share persistent quantile and pair-moment state.**

   Files: `core.py` and, if separation improves clarity, new internal `_quantiles.py` and `_moments.py` modules.

   Factor one Numba-compatible P² transition over heights, actual positions, desired positions, observation count, and the five-observation initialization buffer. Use it from the scalar `P2Quantile`, compiled batch path, and new chunk APIs. The current scalar and compiled recurrences agree; this refactoring prevents future divergence rather than correcting a known mismatch between those two paths.

   Represent each pair with count, two accepted means, two centered square-sums, and a co-moment. Share update and finalization logic across execution modes. Store only the upper triangle if convenient, then form the symmetric output. Do not replace pair-specific statistics with one mean or variance per coordinate.

   Acceptance: scalar, batch, and chunked quantiles agree for identical row order, including partitions before and around the fifth observation. Pair-state results match the independent accepted-subset oracle. Initialization, marker ordering within each tracker, and finite-state checks cover constant, monotone, reversed, and skewed inputs. P² is order-sensitive; permutation invariance is not a correctness requirement. Any optional state merge must combine moments using counts and mean differences, never by averaging correlation matrices; P² summaries are not assumed mergeable.

4. **P1 — Implement bounded-memory replay of Algorithm 1.**

   Proposed API: `ForceEstimator.fit_replayable(source_factory, chunk_size=...)`, retaining the existing `fit(X)` convenience API.

   Replay requires `exact_cutover=5` and rejects the whole-small-batch fallback. The array API retains that fallback: exact linear quantiles for an entire batch with `N < exact_cutover`, otherwise P² from its usual five-observation initialization. Review amendment: add a separate `exact_prefix=0` option to batch, replay, and incremental quantile APIs. A nonzero prefix must contain at least five rows and is mutually exclusive with `exact_cutover>5`. Exact linear readouts apply through N_exact while standard P² consumes all observations in parallel; later readouts use that warmed state and release the prefix buffer. The paper leaves marker reseeding unspecified, so this declared handoff changes no standard P² markers and promises no later accuracy improvement. Account for O(p*N_exact) additional memory and repeated work for each early readout. Test both sides of the transition and arbitrary chunk boundaries. Default pure P² remains the paper's experimental quantile mode.

   The factory must return a fresh traversal of the same ordered observations. Pass one updates quantiles; its final bounds are frozen. Pass two applies those bounds and updates pair statistics. Validate dimensions, finite values, and input conversion in bounded chunks. Detect inconsistent row counts and changed content/order using a streaming checksum over the validated representation. Reject one-shot iterators or a changed replay rather than silently fitting incomplete or different data.

   Share the same state kernels with `fit(X)` so replay parity is testable. A NumPy-array path can expose slices; conversion from arbitrary Python lists or an entire non-float64 array may still require caller-visible batch storage and must be documented. Do not market that convenience conversion as independent of N. For replay, auxiliary memory is O(p²+Bp) at fixed chunk size B, including validation and conversion buffers; source storage is separate.

   Acceptance: replay and batch agree on quantiles, bounds, per-pair counts, and correlations for the same ordered data in pure-P² mode. Unsupported cutover settings fail explicitly. Changing chunk boundaries does not change the estimator. Exactly two data traversals occur. Increasing N at fixed p and B leaves peak working memory approximately bounded after JIT warm-up. Measure workspace/peak RSS as well as retained state; include all validation masks and temporary arrays. Replay is not a one-pass solution for data that cannot be revisited.

5. **P1 — Implement one explicit online variant from Remark 9.**

   Proposed API: `StreamingForceEstimator(window_size=1000, ...)` with `update(row)`, `update_batch(chunk)`, and `finalize()`. This mode uses pure P² within every logical window and has no batch `exact_cutover` option. The chosen window size is a documented implementation parameter, not a requirement derived from the paper. Review amendment: require more than five observations per logical window, since five never leaves P² bootstrap; warn for 6–49 under Remark 3. The default can use the paper's 1000-observation periodic-update example. Fixed-window errors do not automatically vanish with total stream length, so Proposition 1's batch target is not asserted for this mode.

   Use a previous-window schedule consistent with Eq. 14. The first complete logical window initializes P² quantiles and supplies the first bounds; exclude those calibration rows from pair moments and report their count. Throughout the next window, accept rows against the frozen bounds from the preceding window while fresh P² trackers summarize the current window for the following one. Reset only those current-window quantile trackers at a window boundary; cumulative pair moments retain all previously accepted estimation observations. Keep the logical window boundaries independent of `update_batch` chunk boundaries.

   `finalize()` returns a snapshot of the current cumulative estimate, including a partial estimation window under its existing bounds, and does not change historical acceptance or reset the estimator. Before calibration finishes, it reports that the estimator is not ready. At the exact calibration boundary, it reports “calibrated, no estimation observations” without presenting a correlation estimate. Once estimation begins, insufficient pair counts use the documented degenerate convention with explicit status. Freeze feature count after initialization, validate finite values before incorporating a row, and expose calibration count, estimation count, accepted-pair counts, bound version, and degenerate-pair status.

   This schedule needs O(p²+p) retained state and bounded input-chunk workspace; it need not retain a full window. It computes correlation over historically accepted rows, not over the final batch acceptance mask. Continuously evolving thresholds, exponentially weighted moments, and current-window reset outputs are separate policies that should be deferred until independently specified. Their absence must be explicit; implementing one documented mode does not implement every alternative in Remark 9.

   Acceptance: a small offline oracle records each window's bounds and historical decisions and reproduces every reported pair count and correlation. Future observations cannot change previous decisions. Row-wise and arbitrary chunked calls agree. Memory is independent of stream length at fixed p and chunk size. Include a case where online and final-bound batch results intentionally differ, demonstrating the distinct semantics rather than treating it as a bug.

6. **P2 — Validate approximation and robustness with matched functionals.**

   Files: convergence, P², TER, and scalability scripts; `protocols.py`; targeted algorithm tests.

   Use the same tails, lambda, epsilon, TER cap, centering, and acceptance schedule in each approximate/exact comparison. Current paper-mode FORCE and TP-TER largely satisfy this for batch execution. Current legacy-mode convergence still compares historical FORCE with the paper-style capped TP-TER functional; label it as a different-estimator comparison or remove it from quantile-convergence reporting. A matched historical exact backend is optional and has lower priority than validating the current estimator.

   Record quantile value and empirical-rank error, bound displacement, acceptance disagreement, accepted-pair counts, retained contamination, and correlation discrepancy. Evaluate both the default uncapped policy and explicitly named fixed/capped variants. For online evaluation, give the exact reference the same calibration exclusion and previous-window schedule; the test-only oracle may retain data, but the production memory measurement must exclude that oracle process.

   Separate approximation error against the same-sample exact functional from error against a known clean correlation or a population trimmed target. For a clean Gaussian with correlation 0.8, joint truncation to approximately +/-3 gives a conditional correlation near 0.79377; this difference is target bias, not P² error. Population trimmed references require independent computation and a stated accuracy/uncertainty budget.

   Stress contamination fraction and magnitude independently: one-sided replacement, symmetric heavy tails, clustered rows, cellwise corruption, rare extreme bursts, and adversarial early observations. Compare random, sorted/reversed, outliers-first, and outliers-last ordering using paired samples. Capture the known 2% one-sided-contamination failure of uncapped TER as a documented counterexample, not a test demanding a favorable RMSE. Likewise, a capped TER does not make P² initialization adversarially robust. Use independent data/order replicates for statistical variability and separate fixed-input repetitions for timing.

   Review amendment: the paper benchmark uses independent seeded permutations of one fixed dataset, shared across methods within a run, with a fixed reference. Its RMSE intervals concern mean error over random orderings conditional on that dataset. Keep fixed-order timing as an explicit option and the legacy default. Record replicate, data, permutation, and reference identities and compute Section 3.5 paired timing tests by those identities, never row position. Failed/missing pairs and undefined inference remain explicit. Adopt Section 3.2.3's dataset-specific Spearman genomics reference over Section 2.4.3's generic FastMCD description and record that interpretation in provenance.

   Acceptance: each diagnostic calls production code and an independent reference; no private competing production recurrence remains. Reports identify estimator, quantile backend, bound policy, execution schedule, and target. A failure is explained at the quantile, bounds, acceptance, or moment stage. No gate demands a published decimal value, a universal P² accuracy threshold, or an unproved 25% robustness guarantee.

**Completion and sequencing**

Complete work in order: specification and oracle -> numerical fixes -> shared state -> replayable batch -> delayed-window online -> matched diagnostics -> documentation and examples. The first two stages gate all refactoring; replay parity gates the online extension. Each stage should be a reviewable change with its own behavioral tests.

The first milestone is a verified, numerically stable implementation of the formal two-pass estimator with a bounded-memory replay API. The second milestone adds one precisely defined causal variant. Both preserve the current corrected batch default. Performance changes, including matrix-product accumulation or a language rewrite, follow only after these semantics are established and must satisfy the same oracle and memory requirements. Dense mask/data products must not silently replace the bounded-memory path.

Completion means the formal equations, intermediate quantities, online schedule, failure policies, and memory behavior are all tested against the declared contract. It does not mean the original paper's inconsistent claims have been proved or its historical tables have been recreated.
