## Executive result

The primary estimator implements final-bound Algorithm 1 through array `fit(X)`
and bounded-memory `fit_replayable(source_factory, chunk_size)`.
`StreamingForceEstimator` implements a separate previous-window causal policy
from Remark 9. The historical result-generating behavior is retained explicitly
as `LegacyForceEstimator`. See the current algorithm revision record below.

The historical release audit summarized later in this document was performed from commit
`36c2caebdda08775dd0a8da72aad19a6f2431956`. Existing uncommitted candidate
revisions were preserved, re-audited, and completed in place.

The paper was treated as an immutable audit input. Its SHA-256 before and after
the work is:

```text
a44f2a3a7e085b40f979e1260c6a977f1c71e64e499295bd5b3c9908cc17afac
```

The audit found four distinct classes of discrepancy:

1. The original implementation did not implement the formal estimator. It
   tracked the 5th and 95th percentiles, used a different TER expression,
   centered accepted observations on marginal medians, and adjusted P² markers
   even when their desired-position discrepancy had magnitude below one.
2. The paper contains internal mathematical conflicts: Equation (3) prints
   malformed P² desired positions; Algorithm 1 omits pair indices from
   pair-dependent moments; and the stated 25% breakdown proof ignores the
   uncapped TER's dependence on the 1st and 99th percentiles.
3. Several published experimental descriptions conflict with the paper's
   tables and committed pipeline. These conflicts are recorded rather than
   resolved by inventing missing data or modifying the PDF.
4. The candidate benchmark revisions still reused warmed estimator instances,
   capped the paper-mode Appendix B TER calculation, omitted common CLI/report
   metadata from several runners, refreshed cache retrieval timestamps, and
   could accept mutable S&P/Gemma caches without mandatory provenance
   sidecars. These execution and provenance gaps were revised during the final
   audit.

Status terms used below:

- **matched**: implementation agrees with the paper.
- **revised**: the implementation was changed to agree with the paper.
- **paper erratum**: the printed formula or description is internally
  inconsistent; the standard or otherwise unambiguous interpretation is used.
- **paper inconsistency**: two paper claims conflict and no implementation
  change can make both true.
- **partially applicable**: a theoretical statement is conditional and does
  not establish the stronger surrounding claim.
- **partially implemented**: the batch algorithm is present but an optional
  alternative described by the paper is not.
- **not reproducible**: essential identifiers or selection rules are absent.

## Current algorithm revision (2026-11-06)

This revision implements `ALGORITHM_REVISION_PLAN.md` against release
`ccae8be07aa4eb9d044f0d01fa1d23ddb7c8007c`. The first two historical commits
(`f5c5a23` and `36c2cae`) have identical core code; their incompatible bounds,
centering, and marker updates are retained only in the explicit legacy module.
Published numerical tables are historical evidence, not current acceptance gates.

The current implementation adds:

- One compiled P² transition shared by scalar, array, replay, and online updates.
  Five-row bootstrap and observation order are preserved across chunk boundaries.
- Offset-centered, pair-specific Welford moments with adaptive binary scaling
  and exponent-aware normalization.
  The fixed-mask rescaling regression at units `1`, `1e100`, and `1e-100` now
  returns the same correlation (approximately `0.8488746876271654`). Unsupported
  arithmetic raises explicitly; failed incremental states cannot be finalized.
  Harmless tiny intermediate updates and representable tiny correlations are
  retained without a blanket underflow rejection. Pearson preparation removes
  offsets before scaling, and its independent diagnostic reference keeps extended
  precision through centering and normalization. Capped TER evaluation avoids
  overflowing uncapped intermediate ratios.
- `ForceEstimator.fit_replayable(source_factory, chunk_size=4096)`: exactly two
  traversals, final frozen bounds, bounded conversion/validation, and a SHA-256
  stream checksum plus shape checks. Changed content/order and reused iterators
  fail explicitly. Replay requires `exact_cutover=5`; the alignment follow-up
  below also adds optional exact-prefix readouts.
- `StreamingForceEstimator(window_size=1000, ...)`: exclude the first complete
  calibration window; use its bounds on the next window; reset only the current
  window's quantile trackers, preserving cumulative pair moments. Logical windows
  are independent of input chunks. `finalize()` includes a partial estimation
  window and never readjudicates historical rows or resets the stream. It returns
  `None` before estimation, with explicit lifecycle status. Five-row windows are
  rejected; sizes 6–49 warn that each window repeats small-sample quantile
  estimation. Constructor settings are immutable.
- Accepted counts and compact int8 per-pair validity reasons, with string labels
  allocated only on explicit request. Correlation/count snapshots do not build
  unnecessary diagnostic matrices. Undefined pairs retain zero
  off-diagonal/unit-diagonal compatibility values. Crossed quartiles and
  degenerate lower-tail distances are flagged; no silent reordering, TER cap,
  fallback estimator, or PSD projection is introduced.
- Independent equation and historical-mask references, plus matched exact/P²
  diagnostics under named uncapped/capped/fixed policies. Reports distinguish
  quantile error, bounds/masks/counts, same-functional approximation error,
  clean-target error, observation order, and execution schedule. Legacy
  convergence is explicitly a different-estimator comparison.

Numerical tests use fixed acceptance masks to isolate arithmetic. The full
estimator retains its absolute epsilon branch and one-sided TER definition;
full scale/sign invariance is not promised. Uncapped TER can fail under 2%
one-sided contamination; that counterexample is recorded rather than hidden
behind a successful-RMSE test. A cap does not prove P² robustness under
adversarial initialization/order. Conditional trimmed correlation need not equal
untrimmed clean correlation even if contamination is completely removed.

Memory checks distinguish retained NumPy arrays from input/output and temporary
workspace. Replay uses O(p²+Bp) auxiliary storage for fixed chunk size B; online
retains O(p²+p), with O(Bp) conversion/validation for each supplied chunk. Array
conversion and source-owned buffering are accounted for separately. Process RSS
is sampled after JIT warm-up; samples can miss short-lived peaks and include
runtime/allocator overhead. A separate untimed `tracemalloc` run measures tracked
allocations, not every native allocation. Neither metric alone proves a memory
bound; the chunked source and bounded state structure establish that contract.

### Review repair verification

The follow-up review found that the first implementation's passing tests did not
cover a tiny-update rejection, translation-sensitive reference calculations,
normalization underflow, or overflowing intermediate capped TER calculations.
Those defects are repaired without changing the paper's accepted-pair functional:

- Adaptive binary scaling retains tiny-prefix updates, unequal units and very
  small representable correlations. Column permutations, chunk boundaries,
  large offsets, minimum subnormal values and finite maximum endpoints have
  targeted regressions. Analytic/Decimal expectations cover cancellation cases
  that a long-double dot-product oracle alone cannot certify.
- Capped TER compares binary exponents before reconstructing the ratio. Tail
  differences and bound products also avoid unnecessary intermediate overflow.
  The independent offline bound reference uses 80-digit Decimal arithmetic;
  pairwise reference calculations subtract an observed origin before scaling.
- Batch retains int8 pair-status codes. Online correlation/count/code extraction
  is separate; expanded labels are opt-in. Online windows must exceed five;
  6–49 warn under Remark 3, and configuration is immutable. Its fixed-window
  historical target is explicitly distinguished from Proposition 1's target.
- Benchmarks label repeated fixed-data errors as conditional error/repeatability,
  retain timing intervals, and leave `ci95_rmse` null. Figure validation checks
  common comparison targets, dimensions and data/reference identity across
  methods. RMSE intervals require declared independent replicates and matching
  replicate identifiers.

### Baseline and optional-mode follow-up

The next review identified two remaining issues: descriptions of the optional
quantile mode and unnecessary full-matrix extended-precision baseline work.
`exact_cutover` is now consistently documented as a small-batch exact fallback:
only a complete batch with `N < exact_cutover` uses exact linear quantiles.
Larger batches use ordinary P² initialization. At that revision, the paper's
optional exact-prefix transition remained unimplemented. The alignment follow-up

column-contiguous float64 workspace. Column reductions avoid full-size absolute
value and squared-value temporaries. Only columns whose initial subtraction

same helper. No input array is modified.

### Paper-alignment follow-up

The latest review identified an optional quantile-mode gap and differences in
the evaluation target and replicate design. The follow-up makes these choices
explicit without changing the default bounds or accepted-pair functional:

- `exact_prefix=0` retains pure P². A configured prefix of at least five rows
  supplies exact linear quantile readouts through `N_exact`. Standard P² tracks
  all prefix rows in parallel; the next row switches readouts to that warmed
  state and releases the buffer. The paper does not define a marker reseeding
  rule. This is one declared interpretation of its transition, not a claim that
  exact prefix values initialize improved P² markers. Later estimates equal
  pure P² and can jump at the switch. Incremental quantile, batch, and replay
  APIs share the same transition. The small-batch `exact_cutover` remains a
  separate option; activating both is rejected. Prefix buffering adds
  O(N_exact*p) memory, and repeated early readouts recompute exact quantiles.
- Genomics uses Section 3.2.3's specific Spearman reference in both full and
  smoke paths. Provenance records why that definition takes precedence over
  Section 2.4.3's generic FastMCD statement.
- Paper benchmark runs use shared seeded row permutations with the reference
  held fixed. Fixed-order timing remains an explicit option and the legacy
  default. Reports distinguish conditional order sensitivity from data-sampling
  uncertainty; only the former is estimated by order-mode RMSE intervals.
- Current benchmark reports compute Section 3.5 paired timing tests from
  matched successful finite observations, validating run/data/order/reference
  identities. Missing and failed pairs are counted. Insufficient pairs and
  constant paired differences leave inference undefined. Tests are unadjusted
  for multiplicity and exploratory. The old LaTeX exporter remains archival.
- Crossed-quartile and undefined-correlation policies remain documented
  implementation conventions; no unrequested change to the estimator's target
  or robustness policy is introduced.

### Quantile arithmetic, validity and online target follow-up

This follow-up implements `REVIEW_REVISION_PLAN.md`. Its four findings describe
the earlier 322-test working tree. The repaired implementation preserves the
default equations, exact-prefix handoff and previous-window online schedule.

- P² reevaluates overflowing parabolic candidates in binary-scaled coordinates,
  retaining the mathematical ordering decision between Equations 4 and 5.
  Safe convex interpolation also covers linear fallback, provisional quantiles,
  exact-prefix readouts and exact batch paths. Independent Decimal regressions
  cover extreme finite endpoints, ordinary/tied/reversed streams and all five
  probabilities. The reviewed `1e306` fit now succeeds; the median of opposite
  maximum finite values is zero. Truly unrepresentable bounds still fail.
- Scientific scoring uses explicit per-pair validity and a named reference's
  eligible upper triangle. The main RMSE requires every eligible pair;
  incomplete coverage produces null with a reason. Approximation diagnostics
  may compare the jointly defined set, recording its size, coverage and hash.
  All-undefined estimates cannot receive zero error. Current baselines publish
  validity from their actual transformed samples or covariance; negative
  FastMCD variances are rejected. Empirical FastMCD benchmark references carry
  their own validity masks. Compatibility zero-filled matrices and their
  eigenvalues remain separately labeled.
- All adjacent quantile crossings are exposed. Crossed-IQR compatibility events
  remain distinct from genuine zero IQR and accepted-sample zero variance.
  This adds disclosure, without sorting quantiles or changing the bound policy.
- Benchmark schema 2 separates execution, estimate validity and timing status.
  Failed warm-ups do not suppress requested fits. A first success after failed
  warm-up can warm later runs but supplies no fit timing. Summaries retain all
  requested/attempted/completed/failed/incomplete counts, including all-failed
  methods. Primary means require all requested eligible results; separately
  named success-conditioned and timing-eligible summaries retain their stated
  denominators. Figures reject partial coverage, missing requested runs and
  unwarmed measurements. Legacy FORCE has no validity metadata, so its current
  scientific RMSE is unavailable; archival fixtures remain historical evidence.
- The documented online target is pair-specific correlation under the original
  iid distribution weighted by the probability that an independent size-B
  calibration block accepts each observation. The actual bound policy enters
  that probability. Almost-sure finite bounds, positive acceptance, finite
  selected moments and positive selected variances are required. Neighboring
  contributions share an evaluation/calibration block. Fixed-window randomness
  does not vanish merely by extending the stream, and the target is not a claim
  about clean-population or current-regime correlation under drift.
- `simulate_online_target` pools accepted moments within independent complete
  Monte Carlo replicates. It never averages window correlations. It reports
  independent-replicate standard errors, explicitly allows finite-evaluation
  nonlinear bias, and withholds the overall estimate on a failed or undefined
  replicate. Separate finite-stream and exact-window references are retained.

### Final implementation revision — 6 November 2026

The final review found no new material defect in the default FORCE formulas or
the delayed-window schedule. This revision addresses the remaining diagnostic,
baseline-convention and reporting issues while preserving those algorithms.

- The standalone P² diagnostic now shares the independent Decimal exact
  quantile reference and tie-aware empirical rank interval with the main
  diagnostics. Constant samples have zero rank error; probability generators
  survive repeated use. Finite extreme errors are averaged without overflowing
  their sum. Nonfinite estimates or unrepresentable individual errors raise
  explicitly. Schema 2 records the changed rank definition and exact reference.
- `WinsorizedEstimator` defaults to linear sample quantiles followed by
  clipping, an explicit interpretation of Equation 18's unspecified convention.
  The legacy protocol selects `quantile_method="tail_count"`, retaining the
  historical SciPy result. Metadata records this choice. Method summaries and
  paired timing records preserve parameter identities and reject missing or
  mixed supplied identities within a method. The exact-trimmed baseline's
  description now correctly identifies partition-selected order statistics.
- Online target simulation identifies its finite-replicate expectation and
  both finite-calibration-window and finite-evaluation bias. An unconditional
  expectation also requires almost-sure calibration success and finite-replicate
  estimability; positive population acceptance or observed all-success runs
  do not establish those assumptions. Reports state these requirements,
  retain failure withholding and supply no stationary-target error bound.
- [force-improvement-plan.md](force-improvement-plan.md) records paper errata,
  an algebraic 2% contamination counterexample for the ideal uncapped
  population functional, a conditional rate proof outline, the fixed-window
  target derivation and prioritized research. These are explicitly separated
  from numerical verification and from unproved P² robustness guarantees.

| Equations (1)-(2), contamination and breakdown definitions | matched | These define the evaluation model rather than executable estimator steps. Fixed-seed contamination tests exercise selected contamination regimes but do not establish a breakdown point. |
| Equation (3), P² desired marker positions | paper erratum | The printed cases are malformed and omit the standard five-marker indexing. FORCE uses `[1, 1+(N-1)φ/2, 1+(N-1)φ, 1+(N-1)(1+φ)/2, N]`. Tests check all positions. |
| Equations (4)-(5), P² marker adjustment | revised | The parabolic update with linear fallback is implemented. Interior markers move only when the desired-position discrepancy has magnitude at least one and the neighboring marker spacing permits movement. An independent incremental implementation is compared with the compiled kernel for all five probabilities. |
| Five P² instances at `φ={0.01,0.25,0.50,0.75,0.99}` | revised | The former 5th/95th percentile trackers were replaced. Five observations initialize each tracker; pure P² is the default after initialization. |
| Optional exact-prefix-to-P² transition (pp. 9 and 18) | implemented with declared transition | `exact_prefix>=5` supplies exact linear readouts through N_exact, with standard P² observing every row in parallel; subsequent readouts use that warmed state and release the buffer. No exact-marker reseeding is claimed because the paper leaves the transition unspecified. Batch/replay and incremental quantiles agree. `exact_cutover>5` remains a separate whole-small-batch fallback. |
| Equation (6), location `q50` | revised | Marginal location is the streaming median. |
| Equation (7), scale `(q75-q25)/1.349` | revised with declared edge policy | The paper's IQR calibration is used without an undocumented scale floor. Crossed approximate quartiles trigger a warning and a flagged collapse to zero; this compatibility policy is outside the paper's unspecified negative-IQR case. |
| Equations (8)-(9), TER | revised | `max(1, abs(q99-q50)/(abs(q50-q01)+epsilon))` is used. A raw lower-tail distance below `epsilon` produces `TER=1` and a warning. |
| Equation (10), adaptive thresholds | revised | Inclusive lower and upper bounds are `location ± lambda_scale*TER*scale`, with `lambda_scale=3`. |
| Equation (11), optional TER cap | matched | `ter_max=None` leaves TER uncapped by default; a positive finite cap is available explicitly. |
| Equation (12), pairwise acceptance | revised | A row contributes to pair `(j,k)` only when both coordinates fall inside their own inclusive bounds. |
| Equation (13), trimmed correlation | revised with validity metadata | Each pair uses the means of its jointly accepted observations. Undefined off-diagonal correlations are zero only as an output convention and carry nonzero pair-status codes; scientific scoring respects those codes. Arithmetic roundoff is clipped to `[-1,1]`, and the paper's unit diagonal is retained. |
| Equation (14), delayed/windowed alternative | implemented for one declared policy | `StreamingForceEstimator` excludes one calibration window, freezes previous-window P² bounds during each next window, and accumulates pair moments over historical acceptance. Partial estimation windows are included. Continuously evolving thresholds and exponentially weighted moments remain separate, unimplemented policies. |
| Equation (15) and Theorem 1, claimed 25% breakdown point | paper inconsistency | The proof considers only the median and IQR. The default uncapped TER also depends on `q01` and `q99`; slightly more than 1% one-sided contamination can move an extreme quantile arbitrarily, expand the bounds, and admit arbitrarily large observations. Appendix B's large 5%-contamination TER error is consistent with this omitted failure mode. The implementation retains Equations (8)-(11) and does not claim that the uncapped estimator has a proven 25% breakdown point. |
| Theorem 2, `O(Np²)` full-matrix time | matched | Quantile tracking is `O(Np)` and pairwise accepted-statistic accumulation is `O(Np²)`. Isolated-process measurements confirm approximately linear growth with `N` for fixed `p` and increasing work with `p`. |
| Theorem 3, memory independent of `N` | qualified by execution mode | Replay uses O(p²+Bp) working memory at fixed chunk size B; online retains O(p²+p) with O(Bp) input workspace. Quantile state is O(p), while pair moments, counts/status, and output are O(p²). Array conversion can allocate O(Np). Source storage is separate. Retained-array size alone does not establish peak working memory; scalability reports include post-warm-up process RSS and tracked workspace with measurement limitations. |
| Equations (16)-(18), Pearson, Spearman, and Winsorized baselines | revised | Baselines validate finite 2-D inputs and expose transformed-sample validity. Paper/default Winsorization clips at linear sample quantiles with 5% limits; explicit `tail_count` retains the historical SciPy convention in legacy mode. The paper leaves the sample-quantile convention unspecified. Parameter metadata distinguishes both rules. Ranks/quantiles are computed once per feature; linear quantiles use partitioning, followed by `O(Np²)` correlation. |
| FastMCD baseline | revised | Failure now propagates; there is no silent substitution of ordinary Pearson correlation. |
| Equation (19), RMSE | matched on the declared valid pair universe | Benchmarks compute RMSE against the declared synthetic truth or real-data reference and require every reference-eligible pair to be estimable. Undefined pairs cannot contribute compatibility zeros; incomplete coverage makes the primary metric unavailable. |
| Equation (20), 95% confidence interval | qualified by replicate design | Fixed-order timing repetitions leave ci95_rmse null. Paper-mode random-order runs estimate the mean RMSE over permutations conditional on one fixed dataset/reference, not uncertainty across new samples. Figure inputs require matched replicate/data/order identities. |
| Remark 13 and Section 3.5, varying orders and paired timing tests | implemented with explicit replicate design | Paper-mode runs use shared independent seeded permutations, fresh estimators, and interleaved method timing. Current reports pair by validated identities and expose unusable-pair counts and undefined inference. The paper's unspecified cross-validation procedure is not claimed. |

## Algorithm 1 mapping

| Algorithm stage | Status | Batch implementation |
| --- | --- | --- |
| Initialize five P² estimators per coordinate | revised | The default probabilities and five-sample initialization are centralized in `force.core`. |
| First pass: update marginal quantiles | revised | Every finite input row updates every marginal tracker in input order. |
| Compute location, scale, TER, and bounds | revised | Equations (6)-(10) share one threshold routine used by FORCE and exact trimmed Pearson. |
| Second pass: pairwise acceptance and sufficient statistics | paper inconsistency; revised | Equation (13) requires pair-specific accepted means, but Algorithm 1 initializes `S_j` per coordinate and then updates it inside every pair loop. Production code follows Equation (13): each pair accumulates its own count, online means, second moments, and co-moment over jointly accepted rows. |
| Finalize the correlation matrix | revised | Pair-specific accepted means are used; degenerate pairs are deterministic and finite. |
| Incremental unbounded-stream API | implemented with explicit semantics | Replay preserves final-bound batch decisions. The causal API uses a fixed logical-window schedule independent of input chunking; historical acceptance is never revised. Both reuse the same P² and pair-moment kernels. |

## Theoretical statement audit

| Paper item | Status | Verification |
| --- | --- | --- |
| Proposition 1, consistency for the trimmed target | partially applicable | The implementation computes the stated empirical trimmed functional. The proposition is explicitly conditional on consistent P² quantiles, continuous marginals, finite second moments, and non-vanishing acceptance probability; the test suite verifies recurrence and rank accuracy but does not turn those assumptions into a proof. This batch/replay statement does not automatically apply to reset fixed-window online tracking: the latter accumulates moments accepted under random previous-window bounds whose estimation error need not vanish with total stream length. |
| Claimed `N^-1/2` asymptotic rate | partially applicable | No finite-sample or distribution-free rate is asserted by the package. Quantile-bound error can dominate in the small-sample and heavy-tail regimes documented by the paper. Consistency alone supplies no root-N rate: the estimated-bound contribution needs a rate and suitable moment conditions. |
| Corollary 1, separated contamination | paper inconsistency | The corollary requires the estimated acceptance region to remain the clean region. With uncapped TER, contamination above the extreme-quantile tail probability can move `q99` or `q01` and expand that region even while the IQR remains stable. Even stable bounds that remove every outlier yield the conditional trimmed target, which generally differs from untrimmed clean correlation. For a Gaussian with correlation 0.8, joint truncation near ±3 gives about 0.79377. A cap does not by itself establish the stronger corollary. |
| Table 2 complexity claims | partially applicable | FORCE's `O(Np²)` time and `O(p²)` full-output memory are matched. Spearman ranks each feature once; linear Winsorization and exact trimming select quantile order statistics by partitioning rather than full sorting. All then perform correlation work up to `O(Np²)`. The paper's multiplicative `O(Np² log N)` expression is not a tight bound for these implementations. |
| Repeated `O(p)` FORCE memory claims in Tables 8/A1 and prose | paper inconsistency | Quantile diagnostics alone are `O(p)`, but a full correlation matrix or all pair accumulators require `O(p²)`, as Theorem 3 correctly states. Reports therefore separate retained arrays, output, source/input storage, and measured workspace. |

## API and package changes

The public estimator remains `ForceEstimator`; its constructor is now:

```python
ForceEstimator(
    lambda_scale=3.0,
    exact_cutover=5,
    use_ter=True,
    ter_max=None,
    epsilon=1e-10,
    *,
    exact_prefix=0,
)
```

All parameters and inputs are validated. Inputs must be finite, numeric,
two-dimensional arrays with at least five rows and two columns.
`exact_cutover>5` enables a small-batch exact fallback: an entire batch with
`N < exact_cutover` uses exact linear quantiles, while `N >= exact_cutover` uses
P² from its five-observation initialization. Separately, `exact_prefix>=5`
enables exact early readouts followed by the already-warmed P² state, in array,
replay, and incremental quantile APIs. It is mutually exclusive with a nondefault
`exact_cutover`. The default uses P² for every valid batch, matching the paper's
experimental quantile mode.

`TrimmedPearsonExact` shares the threshold and pairwise-correlation routines.
The broken historical `ExactTrimmedEstimator` name is a deprecated
compatibility wrapper. Historical FORCE mathematics are isolated in
`force.legacy.LegacyForceEstimator` and are selected only by the `legacy`
benchmark protocol.

The package now supports its `src` layout in pytest, has no `gemmapy`
dependency, requires Python 3.10 or newer, ignores generated caches/results,
and exports version `1.1.0`. A freshly built wheel and an isolated editable
target installation both imported `ForceEstimator`, `LegacyForceEstimator`,
and `TrimmedPearsonExact` successfully. The editable target was loaded with
`site.addsitedir`, which processes the `.pth` file generated by setuptools.
Python 3.11 was unavailable on this host, so execution used Python 3.12.3.

## Experimental protocol audit

### Paper protocol

The default protocol follows the paper's formal definitions and prose:

- `N=1000`, `p=10`;
- 10% whole-row standard-Cauchy contamination scaled by 10;
- corrected FORCE, pure P², `lambda_scale=3`, `epsilon=1e-10`, uncapped TER;
- verified ODDS mammography and satellite downloads;
- FastMCD for ODDS, the paper's low-volatility Pearson reference for S&P, and
  Section 3.2.3's Spearman reference for genomics;
- 20 shared random-order replicates with fixed reference and fresh estimator
  instances after separate throwaway warm-up; fixed-order timing is available
  explicitly. Numba and numerical libraries are restricted to one thread.

Actual ODDS files were validated:

| Dataset | Shape | Outliers | SHA-256 |
| --- | ---: | ---: | --- |
| Mammography | `11183 x 6` | 260 | `271ebb568314a856666d3504b4882e21b0ea6e1ba9e648ad256d572a36df597e` |
| Satellite | `6435 x 36` | 2036 | `6feac3112b9c14e1c3e60afc437f2f3d29dc1000119c9f950c628078778d6aa0` |

No synthetic data are substituted if an external download fails. Cache
metadata preserve source URL and retrieval time and add validation time,

date/preprocessing parameters, a retrieval timestamp, and a recomputed
SHA-256; missing, malformed, stale, or corrupted caches are rejected instead
of being silently self-certified.
